# 연재 운영: 비축분, 게시, 기록, 주간 점검

## 비축분
- ledger.json에서 posted:false 인 화가 비축분이다. 목표는 항상 3화. 새 작품은 공개 전에 20화 안팎을 먼저 쓴다(하루 1화 연재 기준 3주치).
- 매 실행: 비축분의 가장 작은 번호를 꺼낸다 → 직전 공개 화 끝, feedback.md 최신 지시와 함께 다시 읽고 `review.md`로 한 번 더 점검 → 약한 곳만 고쳐 게시 → 다음 화를 새로 써서 비축분에 채운다. 비축분이 하나도 없으면 쓰고 바로 올린다.
- 컴퓨터가 꺼져 못 올린 날은 다음 실행에서 하루 한도 안에서 비축분부터 올려 따라잡는다. 번호는 건너뛰지 않는다.
- 같은 날 한도를 이미 채웠으면 쓰기만 한다.

## 게시 (작품마다 방법이 다르니 작품 workflow.md가 먼저)
- 게시 방법(에디터 입력 방식, 확인창 처리, 제출 버튼 위치)은 사이트마다 다르고 자주 바뀐다. 작품 폴더의 workflow.md에 검증된 절차를 적어 두고 그대로 따른다.
- 영문 4개 사이트는 `english-serial.md`.
- 로그인이 풀려 있으면 올리지 말고 원고만 저장한 뒤 알림 도구로 사용자에게 알린다. 가입, 본인인증, 비밀번호 입력은 하지 않는다.
- 올리기 전에 작품 페이지 목록에서 이미 올라갔는지 확인한다(중복 게시 금지). 페이지가 멈추면 탭을 닫고 새 탭에서 다시 하되 올라갔는지 먼저 본다.
- 게시 직후 공개 화면에서 제목, 첫 문단, 마지막 문단, 글자 수가 원고와 같은지 대조한다. 줄바꿈이 깨졌거나 본문이 비었으면 같은 실행에서 고친다.
- 대조가 끝나면 ledger.json에 posted:true, postedAt, 주소를 적는다.
- 실패하면 임의로 우회하지 않고 사용자에게 한국어로 알린다. 규정 위반이 의심되면(AI 표지, 삽화, 분량 미달 등) 올리지 않는다.

## 글자 수 세는 기준이 사이트마다 다르다 (기록된 관측)
- 노벨피아: 표시 글자 수가 공백 제외 집계보다 약 7% 작게 나온다(공식 최소를 넘기려면 여유를 둔다).
- 문피아: 빈 줄을 포함해 세므로 공백 제외 수치보다 크게 나온다(예: 로컬 2,699자가 사이트 3,491자). 두 숫자를 같은 기준으로 비교하지 않는다.
- 웹노벨(Inkstone): 게시 확인 창의 단어 수와 편집기 표시가 다르다(1,743 대 1,656).
- 원고 검사와 사이트 표시 숫자를 함께 남기고, 서로 다르다고 실패로 판단하지 않는다.

## 루틴 메모의 완료 주장을 믿지 않는다 (자동 연재에서 실제로 발생한 일)
루틴 메모리에 "41화 공개 확인, 43화 작성 완료"라고 있었지만 장부와 공개 목록은 40화까지였고 43화 파일은 없었다. 매 실행 시작에 장부(lastPublished), 사이트 목록 맨 위 회차, 원고 파일 존재를 직접 대조하고, 메모 문구만 보고 건너뛰지 않는다.

## 80화 완결형 계획 형식
plan.md에 1~80화를 회차별로 설계하고 모든 복선의 회수 회차를 정한다. 새 설정이 생기면 바로 쓰지 않고 plan.md의 "확정 전 새 설정"에 적은 뒤 확정한다. 완결 회차(예: 80화)는 완결 체크 후 올리고 그 뒤는 올리지 않는다.

## 주간 독자 반응 점검 (주 1회, 보통 일요일 밤)
1. 화별 조회, 추천, 댓글과 작품 전체 조회·추천·선호·알람을 stats.json에 덧붙인다(날짜와 함께).
2. 1화 대비 유지율, 직전 화 대비 15% 이상 빠진 화를 표로 만든다. 최근 공개 화는 아직 못 읽은 독자가 섞여 있어서, 같은 화의 다음 주 숫자와 비교한다.
3. 빠진 화의 원고를 읽고 원인을 추정한다. 추정은 "추정"이라고 쓴다. 숫자가 작으면(화당 수십 명 미만) 판단을 유보한다.
4. feedback.md 맨 위에 새 섹션을 추가한다: 이번 주 관찰, 다음 회차 지시(5개 이내, 구체적으로), 고쳐 볼 만한 이미 올린 회차(이유만), 사용자 결정이 필요한 제안.
5. 연재 루틴은 매 실행 때 "다음 회차 지시"를 읽고 따른다. bible.md와 개요의 핵심 구조(결말, 아크 목표)는 feedback만으로 바꾸지 않는다. 이미 올린 회차 수정, 소개글·제목·표지 변경은 사용자 결정 전에는 하지 않는다.
6. 유입이 문제인지(1화 조회가 적음), 중간 이탈이 문제인지(2~10화 유지율)를 먼저 가른다. 처방이 다르다.

## 사용자에게 알릴 것
- 사이트에서 확인한 숫자와 추정한 원인을 구분한다.
- 사용자 결정이 필요한 것은 한두 줄로 묻는다.
